# 巡检图像发送顺序与弱网计时模块

本包实现 B/C 发送排序、文件字节核对、固定有效速率时间计算和 CSV 导出。所有代码仅使用 Python 标准库，无需 pip 安装第三方包。建议使用 Python 3.11 或更新版本。

重要：用户尚未提供团队共同约定的具体 JSON 字段和返回字典字段。本包的接口 v1 是明确列出的临时接口，不代表已确认的共同约定。拿到团队原文后，对齐输入字段与输出字段，不改变排序和计时原则。代码不负责 A 组整张高清图片、图片切块、识别、GUI 或真实网络上传。

## 1 安装与第一次运行

1. 从 https://www.python.org/downloads/windows/ 安装 Python 3。使用官方安装管理器或安装程序，安装后在 PowerShell 验证 `py --version`。
2. 从 https://code.visualstudio.com/ 安装 VS Code。在扩展栏搜索并安装 Microsoft 发布的 Python 扩展。
3. 解压整个压缩包到例如 `D:\inspection_transmission`，用 VS Code 的“文件 → 打开文件夹”打开它，不要只打开单个文件。
4. 按 Ctrl+Shift+P，选择 `Python: Select Interpreter`，选已安装的 Python。
5. 选择“终端 → 新建终端”，终端当前目录应包含两个 .py 文件。执行：

```powershell
py check_transmission.py
```

预期输出 8 项 `[通过]` 和最后的 `8/8 项检查通过`。如果系统只有 python 命令，全部命令中的 py 可换为 python。不要在 `>>>` 的 Python 交互窗口里输入这些终端命令。路径含空格要用双引号包围。

检查脚本自动在临时目录创建 manifest 和二进制占位文件，测试结束后删除。无需提前准备图片，不修改队友文件。占位文件不是 JPEG，测试数值不是实验结果。模块只检查文件是否存在和字节数，不验证 JPEG 编码，这是为了让字节计时模块不承担图片处理职责；真实 JPEG 的正确性由图片模块负责。

## 3 临时输入接口 v1

每张图片对应一个 manifest.json。固定 4×4 分块，编号 tile_00 至 tile_15，编号的空间对应关系由图片队友固定，不能为了实验效果重新编号。只要块与 ROI 相交就标重点，或采用其他明确的团队规则；必须由队友统一计算，B/C 共用同一标注。

缩略图字段：`thumbnail` 对象，包含 `path` 和 `bytes`。
图块字段：`tiles` 列表，必须有16项，每项包含 `id`、`path`、`bytes`、`is_roi`。

单个条目示意（不是完整清单，不可直接运行）：

```json
{"id": "tile_00", "path": "tiles/tile_00.jpg", "bytes": 12345, "is_roi": true}
```

`bytes` 必须是保存后的真实 JPEG 文件大小，不能填像素数、宽×高×通道数或估计值。`path` 使用相对于 manifest 所在目录的路径，如 `tiles/tile_00.jpg`，用 `/` 分隔，不能写电脑绝对路径。必须有缩略图文件和16个不同的图块文件。清单里额外字段（如图片名、坐标）不影响当前计算，但不会进入输出。

包内 manifest_interface_example.json 是完整字段结构示例，字节数全部是占位值，缺少图片，因此不能直接用于 simulate。不要把它当作真实清单。

## 4 临时返回接口 v1

`simulate(manifest_path, rate_mbps, mode)` 返回 Python 字典：

| 字段 | 含义与单位 |
|---|---|
| mode | B 或 C |
| rate_mbps | 调用时给定的有效速率，Mbps |
| timeline | 按发送顺序排列的17条字典，缩略图加16块 |
| total_bytes | 缩略图与所有图块的实际字节数之和，bytes |
| roi_complete_s | 所有重点块完整到达时刻的最大值，秒；没有重点块时为 None |
| image_complete_s | 所有图块完整到达时刻，秒，包含此前传缩略图的耗时 |

timeline 每条包含：`sequence`（从0开始）、`id`、`path`、`is_roi`、`bytes`、`cumulative_bytes`、`start_s`、`arrival_s`。起点 t=0，无并行传输，无休眠。缩略图仅提供预览，不替代任何高清重点块。

## 5 每个函数怎样工作

`transmission.py`：

- `_read_manifest`：读取 JSON，检查16个编号是否齐全、标注类型、相对路径、文件是否存在、实际字节是否等于清单；任何不符直接报错，不静默纠正数据。不能多个条目重复指向同一个文件。
- `simulate`：核对正速率与 B/C 模式；B 缩略图后按编号，C 缩略图后按重点/背景和编号；依次累加字节，计算时刻；从重点块到达时刻取 max。
- `export_csv`：导出时间表；每行同时保留模式、速率和汇总指标。UTF-8 BOM 编码便于 Excel 打开。None 在 CSV 中是空格字段，不是0。
- `main`：允许终端运行；读取 `--rate`、`--mode`、`--csv` 参数，输出 JSON，失败返回非零退出码。

`check_transmission.py`：

- `fixture`：创建明确标注的接口测试清单，倒序输入、不等文件大小，检查算法是否真的排序和按字节计时。
- `require`、`close`：检查条件和浮点近似相等；使用普通函数，不会受 `python -O` 禁用 assert 的影响。
- `check_pair`：调用 B/C，核对文件一致、编号完整、排序、每行开始/到达、累计字节、总时刻及 ROI 时刻。
- `run_tests`：检查重点靠后、原本靠前、全部重点、没有重点、速率变化、非法输入、错误清单和 CSV。
- `main`：先运行接口测试；有 `--manifest` 时继续核对真实清单。错误会输出 `[失败]` 并返回非零退出码。

## 6 时间公式与手算练习

1 Mbps = 1,000,000 bit/s；1 byte = 8 bit。

第 k 个文件开始时刻 = 前 k−1 个文件总字节数 ×8÷(rate_mbps×1,000,000)。
第 k 个文件完整到达时刻 = 前 k 个文件总字节数 ×8÷(rate_mbps×1,000,000)。

下面仅是手算练习：1 Mbps 下，缩略图1000 bytes、第一块2000 bytes、第二块3000 bytes。缩略图0秒开始、0.008秒到达；第一块0.008秒开始、0.024秒到达；第二块0.024秒开始、0.048秒到达。只把第二块标重点时，ROI 完成是0.048秒。完整模块仍要求16块。

代码从累计整数 bytes 直接计算每次时刻，不反复相加小数时间，也不提前四舍五入。ROI 被多个块覆盖时必须等最后一个重点块完整到达。

## 7 收到队友文件后运行

队友提供目录例如 data/image_001/manifest.json、thumbnail.jpg 和 tiles/ 下16张 JPEG；先对齐团队字段，再运行：

```powershell
py check_transmission.py --manifest "data/image_001/manifest.json" --rate 0.5
py transmission.py "data/image_001/manifest.json" --rate 0.5 --mode B --csv B_05.csv
py transmission.py "data/image_001/manifest.json" --rate 0.5 --mode C --csv C_05.csv
```

CSV 保存在终端当前目录。重复使用同一输出文件名会覆盖前次 CSV。真实清单不符合本临时 schema 时先改接口适配，不要为了通过检查修改真实实验数据。

队友从 Python 界面调用：

```python
from transmission import simulate, export_csv
b = simulate("data/image_001/manifest.json", 0.5, "B")
c = simulate("data/image_001/manifest.json", 0.5, "C")
export_csv(b, "B_05.csv")
# 界面根据 arrival_s 决定何时显示已完整到达的块，模块本身不等待。
```

## 8 真实实验怎样完成

1. 固定图片集、ROI 标注、JPEG 编码参数及图块文件；记录版本。B/C 用同一份 manifest，不重新压缩，不分开生成图块。
2. 团队预先选一组有效速率，例如0.1、0.5、1、5 Mbps。这些仅是可选仿真参数，不代表测得的5G速率。每张图在每个速率调用 B/C。
3. 检查 B/C total_bytes 和 image_complete_s 完全相同，并确认缩略图计入总量。
4. 记录 ROI 提前量 = B ROI时间 − C ROI时间；B ROI时间大于0且两者有定义时，相对改善率 = 提前量÷B ROI时间×100%。无 ROI 图片写 N/A，不按0时间参与统计。
5. 保留零改善图片，汇总全部有效图片的均值/中位数和每张图片结果，不只展示重点靠后的图。
6. 本模块只改变顺序，因此 B/C 文件画质和总流量相同，不能宣称 C 更省流量或提高 JPEG 画质。C 的优势是提前提供完整重点块；任意时刻可见质量的演示交给界面队友。
7. A 组整张高清原图的总字节和完成时间由独立基线模块处理。A 与分块+缩略图的大小可能不同，必须按实际文件统计。

有效速率表示已考虑无线链路效率后可供 JPEG 使用的净速率。当前模型只计算 JPEG 载荷时间，不另加 TCP/IP 头、连接时延、丢包、重传及处理时延。报告写“固定有效速率下的传输调度仿真”，不能写“实测5G网络性能”。团队可以另行解释工业无线巡检、弱覆盖和上行受限场景；真正的动态带宽自适应尚未包含在此模块中，题名和报告应与实现阶段一致。
