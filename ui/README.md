# 石韵涵：界面与接收端

本目录把仓库里的两个模块接进同一界面：邱雪瑶的 `inspection_image/image_processing.py` 生成图片块，朱雨萱的 `transmission_starter/transmission.py` 计算发送顺序和时间。默认使用这两个模块；内置测试后端保留为单独选项。

当前完成的是 **B/C固定有效速率的软件联调**。不含A组、自动目标检测、自动读数、动态画质、丢包重传或真实5G/Wi-Fi收发。真实照片也不等于真实网络实验。

## 1. 在自己的电脑上启动

下载整个仓库，而不是只下载本文件夹。用VS Code打开仓库根目录（同时能看见 `inspection_image`、`transmission_starter`、`ui` 三个文件夹）。建议Python 3.11或更高版本。

第一次在终端执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r ui/requirements.txt
.\.venv\Scripts\python.exe start_ui.py
```

若电脑只有 `py` 命令，第一行改为 `py -3 -m venv .venv`。后两行仍使用项目环境的完整相对路径，不必激活环境或修改PowerShell执行策略。

以后只需执行最后一行。启动器自动选择8501到8510之间的空闲端口，并打开本机浏览器。关闭时在终端按Ctrl+C；只关闭浏览器不会停止程序。

也可在已安装依赖的环境中直接运行：

```powershell
python -m streamlit run ui/app.py --server.address 127.0.0.1 --browser.gatherUsageStats false
```

## 2. 第一遍怎么操作

1. 运行模块保持“队友正式模块（软件仿真）”。没有真实照片也可先选“内置测试图”检查功能，图上的数字不是真实实验答案。
2. 有公开样本目录时选择“公开仪表样本”；也可以上传自己的JPG、PNG、WebP，或将照片放在 `ui/images` 后选择该文件夹。
3. 填设备编号。检查红框是否完整包含数字、小数点和判断所需的单位；用左、上、右、下四个坐标调整。
4. 看原图核对参考读数，只有确定后才勾选“我已人工核对本图读数或状态”。不清楚就留空；模型不会替你识别数字。
5. 同一设备且视角固定时可以点击“保存此设备ROI”。尺寸匹配只代表可以载入，仍须检查拍摄角度有没有改变。
6. 选0.25、1或5 Mbps，点击“生成 B / C 对照”。
7. 依次查看“回到开始”“查看缩略图到齐”“查看 C 组重点到齐时刻”“查看全部到齐”。左右始终用同一个模拟时间。
8. 下载B、C时间表和本次参数记录。它们也会自动存入 `ui/logs`。

换照片、ROI或速率后需重新点“生成”；只拖动时间滑块不会重新编码，同一张图同一ROI改变速率也会复用已有JPEG。ROI已经到齐不代表人一定读对了数字。

## 3. 各文件与代码段负责什么

| 文件 | 作用与阅读顺序 |
|---|---|
| `../start_ui.py` | 根目录启动入口，调用共用启动器，不处理图片。 |
| `start_environment.py` | 找空闲端口、启动Streamlit、确认服务可用、打开浏览器；按Ctrl+C会收尾关闭服务。 |
| `start_app.py` | 在ui目录内启动的等价入口。 |
| `app.py` | 页面主流程，代码按下面六段组织。 |
| `team_bridge.py` | 集中转换三人现有字段；调用队友函数，不另写排序或传输算法。 |
| `ui_support.py` | 图片预览、ROI保存、接收端恢复、CSV导出。 |
| `sample_data.py` | 读取公开样本清单，检查来源字段、图片指纹、尺寸和ROI；不下载或自动识别。 |
| `demo_backend.py` | 独立的旧接口测试后端和合成图生成器；只有手动选择测试模块时才使用它的编码/计时函数。 |
| `test_team_bridge.py` | 检查队友接口转换、JPEG和清单不被修改、字节和时间。 |
| `test_receiver_integration.py` | 检查接收端只在文件完整到达后读取，以及B/C最终画面一致。 |
| `test_app_integration.py` | 检查真实页面状态、参数改变和图块复用。 |
| `requirements.txt` | 两个直接依赖及本轮使用的版本。 |

`app.py` 的六段：

1. 创建页面与侧栏，选择正式队友模块或内置测试模块。
2. 读取照片、校正手机EXIF方向，载入参考答案；换照片或改答案会取消旧的人工确认。
3. 载入设备ROI，在原图副本上画框和网格；坐标基于校正方向后的原图。
4. 点击生成后只编码一次，计算B/C，检查顺序、累计字节和时间，写入CSV及JSON。
5. 共用时间滑块，调用接收函数恢复两幅画面。原图预览绝不会被用作接收端底图。
6. 展示本次结果、提供下载，解释实际处理耗时与模拟时间的不同含义。

`ui_support.py` 中，`save_preset`保留其他设备配置后保存；`matching_preset`检查设备和尺寸；`render_received`先画空白，缩略图完整到达后铺底，再贴已完整到达的块；`events_csv`输出Excel能打开的UTF-8 BOM文件。显示的恢复耗时只是本次解码、缩放和拼接时间，不是累计端到端时延。

## 4. 现在怎样对接三人的字段

**图像模块输出的原始 `manifest.json` 是数据来源。不要为了界面手工改它，也不要分别为B/C重新压缩。**

| 原图像清单 | 传输模块使用的视图 | 界面内存中使用的视图 |
|---|---|---|
| `tile_id: 0..15` | `id: tile_00..tile_15` | `packet_id: tile_00..tile_15` |
| `payload` | `path` | `file` |
| `size_bytes` | `bytes` | `nbytes` |
| `box` | 保留源清单供界面读取 | `bbox` |
| `priority=1`重点，`0`背景 | `is_roi=true/false` | 缩略图0、重点1、背景2 |
| `image_processing_seconds` | 不改变 | 换算为毫秒显示，并保留计时范围说明 |

现有传输模块要求从一个JSON文件读取。因此桥接文件会在原清单同目录生成 `manifest_for_transmission.json`：只转换字段，同样指向那17个JPEG，不复制或重新编码图片，不替换原清单。B/C共用此文件，它不计入当前JPEG载荷字节。传输返回的 `timeline`、`image_complete_s`在桥接层映射为界面的 `events`、`full_complete_s`，不改变时间值。

队友后续统一字段时，应集中调整桥接文件并重跑检查，不在三个地方分别猜字段。更换模块源文件后重启界面。

## 5. 日志与数据的含义

- `ui/data/ui_inputs`：用户输入图片的本地副本。
- `ui/data/ui_runs`：每批17个JPEG、原始清单及传输字段视图。
- `ui/data/roi_presets.json`：设备预设，按设备编号和处理后尺寸保存。
- `ui/logs/*_B.csv`、`*_C.csv`：同一批图片的两种发送顺序和时刻。
- `ui/logs/*_record.json`：来源、图片SHA256、ROI、有效速率、人工核对状态、清单指纹和队友模块指纹；清单位置为相对ui目录的路径。

SHA256是文件指纹，便于确认两次使用的是同一个文件，不是机器学习算法。未人工确认的参考文字不进入 `ground_truth`。

当前日志均标“接口联调，非正式实验”。数据量统计为缩略图加16块的实际JPEG字节，不含清单、网络协议头或重传。B/C必须总字节数和整图到齐时间相同；重点区域可以提前，也可能没有改善。

运行生成的数据与个人照片默认被Git忽略。随仓库附带的公开调试样本须单独提供来源和许可说明；它们的ROI只是已有数字标注组合后的初值，不表示自动检测已实现。

本目录附5张Mendeley公开真实电表照片（CC0），来源与校验见 [SAMPLE_SOURCE.txt](SAMPLE_SOURCE.txt)，预览见 [SAMPLES_PREVIEW.jpg](SAMPLES_PREVIEW.jpg)。原JPEG字节保持不变，正确读数全部留空等待人工核对；照片是仪表近景、背景有限，只作联调，不能代表正式巡检样本分布。

## 6. 如何检查接入没有出错

在仓库根目录执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s ui -p "test_*.py" -v
```

软件检查会创建临时合成图片；通过不等于完成真实巡检实验。真实图片仍需三人检查ROI、人工核对读数，再用相同图片与参数复查四个显示时刻。

这一阶段不把“ROI到齐”直接记为“读数正确”。后续需要独立的观察者填写指定时刻看到的数字，并与预先核对的答案比较。
